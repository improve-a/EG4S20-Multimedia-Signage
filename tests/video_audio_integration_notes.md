# Unified unencrypted video/audio subsystem verification

The test instantiates production `video_transition`, `video_extensions` with `ENABLE_AUDIO_VIS=1` (pixel_adjust → audio_visualizer → osd_overlay), the actual baseline `video_rgb_to_axis_640x480` instance used as hdmi_axis_video, and real audio_media parsing WAV bytes from complete sector transactions. Clock rates remain 100MHz system and 25MHz pixel/audio, with 48kHz PCM. It generates two 800x525 raster frames with full 640x480 active video and standard 96-pixel HS/2-line VS pulses. Ten milliseconds of real-rate audio pre-run creates a nonzero history before video starts.

Frame 0 disables both overlays and uses brightness +40/unity contrast; all active and blank RGB/sync are compared against an independent saturation/flooring reference. Frame 1 enables both overlays and commits brightness -1/contrast 0.50 during blanking after previous packets have drained. A staged reference checks 5 registered RGB/HS/VS/DE stages (one transition + four extension) and a sixth AXIS stage on every cycle, all SOF/EOL/valid pulses, all waveform/background and peakbar pixels against a reference RAM populated from the actual audio input stream, progress endpoints, and independent text/font anchors. Other OSD character pixels are captured for visual inspection; they are not all reconstructed as an independent font implementation.

Run video_audio_integration_002 passed in 165.016 seconds: 1,090,060 cycles, 614400 pixels, 2 SOFs, 960 EOLs, 2083 ordered real WAV PCM frames, 116 nonzero L/R trace pixels and 4764 colored peak-bar pixels. It used the actual WAV output cadence directly, before the production shared tone-cadence fix. Its full actual RTL PPM is preserved and PNG is named video_audio_integration_002_preview.png. Visual inspection found the title lacked its first H. The first-row H/X glyph anchors coincided, so this was outside that run's assertions; the known preview issue is explicit in its manifest. Root fixed the title to exactly 12 bytes and the final test adds row2 H anchors that distinguish H from X.

Earlier run video_audio_integration_001 failed at frame1 x5/y450 after detecting the subtitle's missing T: its 33-byte literal overflowed a 32-byte register. Root fixed it to the exact 24-byte caption plus eight explicit spaces. The failed input snapshot, simulator log and partial PPM remain evidence. It was a real OSD functionality bug, not a masking waiver.

The final run 003 additionally instantiates actual baseline tone and ACR RTL. Production selection is copied (prefill selects WAV while PCM is still held silent), `audio_valid` always follows the original tone's 48kHz cadence, and audio data selects held WAV samples. The waveform reference samples this actual final HDMI input stream, distinguishing initial fallback tone from selected WAV before checking PCM order. ACR checks all steady-state CTS/N packets against 25000/6144. Previous two mux diagnostic tests independently demonstrate both a long and short old-cadence handover glitch and their removal by this shared cadence.

FIFO/history RAM changes are recorded in video_audio_ram_fix.diff and video_audio_ram_fix_manifest.json, with fresh RAM-related unit passes. Root's audio_media number/ternary formatting repair is functionally identical to old simulation sources; prior manifests retain their historical hashes and the final run stores the current source hashes. The supported fehdl BRAM annotation and unreset enabled synchronous RAM read ports preserve the same external latency; no old IP is modified by this task.

Scope is video/audio subsystems with a generated video source and a WAV sector-byte model. Encrypted HDMI, DDR/SDRAM transactions, actual SD SPI card responses, board clocks/pins, hardware programming and full-system simulation are excluded. Shared physical-reader SPI-rate fairness was separately tested by audio_arbiter_003. A passing simulator result does not establish timing closure, bitstream success or hardware correctness.
