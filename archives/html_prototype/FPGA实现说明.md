# FPGA 可实现性说明

HTML 原型是视觉与交互的设计参考。下面说明每一部分在 EG4S20BG256 上如何实现、需要简化哪些地方。当前工程已有的资源占用：LUT 46.74%，BRAM 54.69%，Setup Slack +0.140 ns。

## 图层划分（原型中勾选"显示图层边界"即可看到）

| 图层 | 原型内容 | 上板实现 |
|---|---|---|
| A 静态层 | 背景光、产品图、大字标题、参数、分隔线、双图对比画面 | 每页一张 640×480 BMP 存放在 TF 卡，由现有链路 TF→SDRAM→HDMI 显示。浏览器截图即可作为 BMP 母版 |
| B OSD 层 | 页码与进度格、字幕卡片、讲解字幕、频谱条、放大小地图 | 字幕卡片底板可以画进 BMP（固定位置），文字用现有 OSD 字库叠加；页码和进度格只需少量矩形比较 |
| C Sprite 层 | 小安的身体和眼睛 | 建议用 RTL 实时计算形状，不占用 BRAM（见下文） |

字幕卡片固定在 (24,386)–(510,458)，小安固定在 (520,368) 起的 104×100 区域，两块都不压产品主图。因此 B、C 层可以只在这两个矩形内做像素判断，其余区域直接透传 SDRAM 数据。

## 小安的上板方案（推荐方案不需要 BRAM）

身体：用圆方程 `dx² + dy² < r²` 判断，再按行加一个小的半径偏移表（32 项）实现呼吸、压扁和形变。倾斜改成按行水平错位（`dx += k·dy`），不做真正的旋转。
眼睛：两个椭圆比较器。眨眼时 `ry` 从 6 降到 1，视线移动就是改变眼睛中心偏移 `(ex, ey)`。
运动：原型里所有弹簧都可以写成定点数，每帧（VSYNC）更新一次 `v += k·(t−x) − d·v; x += v`，状态量只有 gx、gy、tilt、squash、blink 五个。原型运行时会把 `bot.state = {x, y, blink, tilt, mode}` 暴露在页面上，这就是 RTL 需要的完整状态向量。
关键路径：乘法放进 18×18 DSP，并插入一级流水线。比较器在像素时钟下工作，弹簧在 VSYNC 下工作，可以缓解目前很紧的时序余量。
备选方案：如果 RTL 余量不够，可以改用预渲染精灵，例如 8 帧、64×64、2 bpp，约 64 Kb，能放进剩余的 BRAM。

## 联动逻辑

原型里只有一个主时钟和一个换页事件 `go()`。按键、导航和自动轮播全部走这个入口；轮播计时从上一次换页开始累积，转场进行中不触发下一次换页。测试结果：间隔 5.4 s 时，实测换页时刻为 5.41 / 10.82 / 16.24 / 21.66 s，没有漂移。
上板时对应一个 `page_change` 脉冲，同时送给转场模块、OSD 字幕模块和小安的状态机，保证三者同步：

```
0 ms      视线跳向新页面进入的方向，眼睛微张
90 ms     身体顺着视线倾斜，上半身前倾，轻微弹起
420 ms    视线跟随转场遮罩扫过画面
1100 ms   转场结束：身体回正，回弹压扁一下，看一眼产品
1550 ms   视线转向观众，开始讲解；讲解结束后回到待机
```

## 需要简化的地方

- 转场：原型使用遮罩揭示并叠加分层动画。上板建议使用现有转场模块里的水平擦除，与原型方向一致即可。
- 字幕逐字显示：OSD 每帧多显示 N 个字符就能实现，几乎不增加逻辑；标点处的停顿可以省略。
- 局部放大：原型对静态层做真实的 1×–3× 放大，可以拖动。对应现有的缩放模块，以最近邻或双线性方式从 SDRAM 读取放大窗口。
- 音频可视化：原型默认是视觉模拟，界面上标注"模拟"。载入本地 WAV 后改为浏览器实时 FFT。上板应该接现有的音频可视化模块，用 9 条带宽即可。
- 静态层中的光晕、颗粒纹理、渐变、阴影都已经画在 BMP 里，FPGA 不需要计算。
