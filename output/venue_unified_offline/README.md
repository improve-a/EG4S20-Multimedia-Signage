# 六页 Unified 离线交付

本轮仅进行 RTL 开发、软件仿真、TD 完整构建与素材文件打包。
当前实现与验证状态由最终 `STATUS.json` 和 `FINAL_REPORT.md` 给出。
TF 卡物理布局及新版位流实板表现均为 **NOT_TESTED**，不继承上一版的实板结论。

## 播放逻辑

- 上电或逻辑复位默认日常模式，只在 UI-01、UI-02 之间循环。
- 在 PLAY 操作页，KEY2 短按并松开：当前模式内下一页；长按约 1 秒：切换
  日常/应急模式，一次长按只切换一次，松开不会额外翻页。
- 进入应急模式从 UI-03 开始，在 UI-03、UI-04、UI-05、UI-06 内循环；返回日常
  从 UI-01 开始。手动与自动轮播均限制在当前组内。
- 切换模式时若读图或显示提交正在进行，先完成已占用缓存的事务与显示确认，
  然后加载最新选择模式的首图。它不是强制中断正在进行的 SD 读取。
- KEY2 在 BRIT、CONT、TIME、OSD、TRAN、ZOOM、VOL 参数页仍用于原有加值/切换，
  长按不会切换内容模式；KEY3 的短按暂停/长按静音、KEY4 的短按轮播或参数减值/
  长按操作页切换保留。
- 扫描表容量为 8。当前产品使用前六个物理发现位置，位置 6、7 为额外容量，
  不加入上述六页分组。通用模块未启用内容分组时可以遍历全部已发现图像。

## 媒体文件

`media/` 包含六张原始 640×480 BMP24 和一个 80 秒 PCM16/48k 单声道 WAV，
以及顺序清单、SHA256SUMS 和格式/内容校验记录。图片像素内容沿用既有 UI 设计。
WAV 独立于页面和内容模式运行，切换日常/应急不会切换或重播音乐；结束后静音。
静态页面的模拟预警、疏散示意及恢复文字不代表传感器或实际告警控制。

预期图像顺序：UI01、UI02、UI03、UI04、UI05、UI06。播放器仍按物理 LBA 发现文件，
不读取 FAT 目录；文件名或复制顺序不能证明实际播放顺序。头部扫描范围仍为
LBA 0–131071，文件必须物理连续。本轮仅检查工程目录内的文件，不检测或写入卡。
实际连续性、物理顺序及旧数据残留留给后续部署验证。

顶层目标扫描数为 8，因此仅有六张图时会扫描到范围末端后加载首图。
默认 OSD 及波形保持开启；完整产品画面的 OSD 设置沿用原有功能。

## 复现入口

在仓库根目录运行：

```sh
python3 scripts/package_unified_offline.py --validate-only
python3 scripts/make_unified_test_vectors.py
```

定向仿真配方见 `tests/unified_media_notes.md`，构建使用既有
`scripts/build.py` 的唯一运行编号和 Windows NTFS 源码快照；本轮确切编号、
输入哈希、工具身份、运行结果和时序限制由最终报告列出。
